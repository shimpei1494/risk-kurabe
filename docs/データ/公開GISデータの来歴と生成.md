# 公開GISデータの来歴と生成

## 目的

ハッカソン版`risk-data-v1`で使用する公開GISデータについて、取得元、収録範囲、加工方法、生成物、検証結果および既知の制約をまとめる。

入力ファイル単位のURL、ファイル名、サイズ、取得日、ライセンスおよびSHA-256は[`data-manifest/sources.lock.json`](../../data-manifest/sources.lock.json)を正本とする。コマンドと必要ツールは[`scripts/data/README.md`](../../scripts/data/README.md)、変換の詳細は`transform-*.sh`を参照する。

元のMVP計画で中核データとした3系統は、すべてR2から利用できる。

R2にはGIS成果物23件と、`manifest.json`、`coverage.json`、`checksums.json`のメタデータ3件、計26オブジェクト（約1.29GB）を配置している。

## 入力データ

### A31a 洪水浸水想定区域（想定最大規模）

- 提供者: 国土交通省
- 配布元: 国土数値情報 A31a 2025年度
- 入力形式: 都県別GeoJSON ZIP 7件
- 対象都県: 茨城、栃木、群馬、埼玉、千葉、東京、神奈川
- 取得日: 2026-07-17
- 利用条件: CC BY 4.0
- 収録区分: 洪水予報河川・水位周知河川の想定最大規模

`A31a_201`から河川番号、`A31a_202`から河川名、`A31a_203`と`A31a_204`から管理者、`A31a_205`から浸水深区分を取得する。

### A53 洪水浸水想定区域（多段階）

- 提供者: 国土交通省
- 配布元: 国土数値情報 A53 2025年度
- 入力形式: 関東地方整備局版GeoJSON ZIP 1件
- 入力範囲: 配布ファイル`A53-25_83_GEOJSON.zip`
- 取得日: 2026-07-17
- 利用条件: CC BY 4.0

入力に含まれる年超過確率は1/10、1/30、1/50、1/100、1/150、1/200。A31aの河川番号先頭6桁を水系コードとして、A53の水系コードと関連付ける。

収録された7水系のうち、久慈川、那珂川、利根川水系（中川・綾瀬川）、多摩川、鶴見川、相模川はA31aと関連付け済み。富士川水系はA31a管理河川データに同一水系コードがなく、`unmatched`として記録する。公開されていない水系・降雨規模の組み合わせは、区域外とせず`unpublished`として扱う。

### 東京都「地震に関する地域危険度測定調査（第9回）」

- 提供者: 東京都都市整備局
- 基準時点: 2022年9月
- 入力形式: 全町丁目Shapefile ZIP 1件、全町丁目CSV 1件
- 取得日: 2026-07-17
- 利用条件: CC BY 4.0

Shapefileの`ID`は公式町丁目コードではなく連番のため`source_id`として保持する。区市町村名と町丁目名を組み合わせた`town_key`でCSVと形状を1対1結合し、建物倒壊危険度、火災危険度、地盤分類などを正規化する。

## 加工方法

すべての入力はダウンロード時に`data-manifest/sources.lock.json`のファイルサイズとSHA-256を照合し、不一致の場合は停止する。

1. GDALで入力を読み込み、不正形状を修復する。
2. 座標系をWGS84（EPSG:4326）へ統一する。
3. データセット固有の属性を共通の判定属性へ正規化する。
4. 空形状を除外し、件数と属性スキーマを検証する。
5. ブラウザのbbox Range検索用に、空間インデックス付きFlatGeobufを生成する。
6. Tippecanoeで地図用ベクトルタイルを作り、PMTilesへ変換する。
7. `manifest.json`、`coverage.json`、`checksums.json`を生成する。
8. 検証後、`risk-data/v1/`へ版付きでアップロードする。

主なスクリプト:

- [`transform-a31a-kanto.sh`](../../scripts/data/transform-a31a-kanto.sh)
- [`transform-a53-kanto.sh`](../../scripts/data/transform-a53-kanto.sh)
- [`transform-tokyo-regional-risk.sh`](../../scripts/data/transform-tokyo-regional-risk.sh)
- [`upload-risk-data.sh`](../../scripts/data/upload-risk-data.sh)

## 検証と再生成

ローカル成果物の全量検証とアップロード:

```bash
vp run data:a31a:validate
vp run data:a53:validate
vp run data:tokyo-risk:validate
vp run data:upload
```

R2配置後のRange読込み検証:

```bash
vp run data:a31a:verify-remote
vp run data:a53:verify-remote
vp run data:tokyo-risk:verify-remote
```

2026-07-30の移行時に、3系統すべてのローカル検証、R2上のbbox Range読込み、HTTP `206 Partial Content`および成果物の内容を確認済み。

## 既知の制約と不足データ

### 公開データの収録範囲

- A31aは関東全河川の網羅データではない。「その他の河川」を含まないため、値がないことを常に浸水リスクなしとは解釈しない。
- A53は水系・降雨規模ごとに公開状況が異なる。未公開の組み合わせを区域外として扱わない。
- 富士川水系のA53成果物は存在するが、現在のA31aから水系を特定する判定順序では関連付けられない。
- 東京都地域危険度は東京都内の相対評価であり、東京都外の安全性を示すデータではない。島しょ部は収録対象外。

### 行政界

座標だけから都県コードを決定するための行政界データは、現在の成果物に含まれていない。住所候補から調査する通常フローではYahoo住所検索の都道府県コードを使うため、中核の地点調査には影響しない。

一方、ADR-0014の共有リンクは座標だけを保持する設計である。そのまま共有リンクを実装すると、復元した座標の都県を信頼できる方法で決定できない。実装前に次のどちらかを決める必要がある。

1. 版管理した行政界データを追加し、座標から都県コードを判定する。
2. ADRを変更し、検証済みの都県コードを共有フラグメントへ含める。

ピンを都県境界をまたいで移動した場合も同じ課題があるため、行政界または再ジオコーディングなしに元の都県コードを使い続けないよう注意する。
