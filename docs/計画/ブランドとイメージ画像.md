# 「TOKYOりすくらべ」ブランドとイメージ画像

> ブランド制作は現行版へ反映済みです。以下は制作方針と成果物の対応を残す記録です。

## 名前

表示名は「TOKYOりすくらべ」とする。

- `TOKYO` は、このアプリが東京都の公開データを深く扱うことと、都市の場所選びを支えることを伝える。
- `りすくらべ` は、怖さを煽らず、複数地点を同じものさしで見比べる体験をやわらかく伝える。
- 英字とひらがなの組み合わせを正式表記とし、「Tokyo」「リスクくらべ」などへ表記を揺らさない。

アプリの対象は東京だけではなく関東1都6県である。誤解を避けるため、名称の近くには「関東の災害リスク比較サービス」と表示し、本文では「関東の洪水浸水リスクと、東京都の地震危険度を確認できる」と明記する。

パッケージ名、Worker名、R2バケット名、ストレージキーなどの内部識別子 `risk-kurabe` は、表示名とは別に扱う。ブランド変更だけを理由に変更せず、URLや保存データの移行が必要になったときに別途判断する。

## ビジュアルの核

主題は「災害そのもの」ではなく、**同じ東京・関東の中でも場所によって異なる公開データを、落ち着いて見比べること**。

### シグネチャー

地図の等高線のような2つの不規則な輪郭を、中央の比較軸で左右に見比べる「比較する地形」を共通モチーフにする。浸水・火災・倒壊を直接描写するのではなく、地点、地図、差分を表現する。

避ける表現:

- 炎、津波、倒壊家屋など、恐怖を強く喚起する災害写真
- 東京タワー、スカイツリー、富士山だけに頼る観光ポスター風の表現
- 盾、チェックマーク、緑一色など「安全を保証する」と誤認させる表現
- 生成画像に細かな地名、数値、凡例を描かせること

## 画像を3用途に分ける

### 1. ロゴマーク

最初に作る。16〜48pxでも判別できる単純なベクターとし、SVGを正本にする。

- 2地点を表す2つの点
- 地形を表す2つの輪郭
- 比較を表す中央の余白または軸
- 文字を入れず、単色でも成立させる

現行版では、`public/brand/app-icon-512.png`を大きなブランドマーク、
`public/brand/icon-192.png`をヘッダー・フッターなど小さな表示用のマークとして採用している。

### 2. ホームのキービジュアル

ロゴの「比較する地形」を拡張し、地図の一部を切り取ったような横長の図版にする。写真ではなく、編集可能なSVGまたはコードで描く。

- 左右または上下に2地点を置く
- 水色、黄土色、橙色の半透明レイヤーで、異なるリスク指標を示す
- 実際のハザードマップに見えすぎない抽象度を保つ
- 人物や建物を置く場合も、主役は比較する地点とデータにする

### 3. OGP画像

キービジュアルを1200×630へ再構成する。文字とロゴはHTML/SVG側で正確に組み、生成AIへ文字を描かせない。

必須要素:

- `TOKYOりすくらべ`
- `関東の災害リスク比較サービス`
- 比較する地形のモチーフ
- 小さく「公開データをもとに1〜3地点を比較」

## 色と書体

既存UIとの連続性を保ち、画像だけ別ブランドにしない。

| 役割 | 色 |
| --- | --- |
| 東京ティール | `#2F8F87` |
| 深いティール | `#134540` |
| 地図の紙色 | `#F0EEE9` |
| 墨色 | `#55524A` |
| 水域の青 | `#5A8FC7` |
| 注意の橙 | `#E0763F` |

- 日本語の表示・ロゴタイプ: Zen Maru Gothic 900
- 本文・注釈: Noto Sans JP
- `TOKYO` は日本語名と一体で読めるよう、字間を広げすぎない

## 制作順と現行成果物

1. ロゴマークを小さな表示でも判別できる形に整理した。
2. ヘッダー・フッターへ`icon-192.png`を反映した。
3. ホーム用の`hero-map-scout.jpg`、OGP画像およびfavicon一式を配置した。
4. 元データは`docs/brand/source/`に残している。

生成AIは、地形の輪郭や紙・インクの質感を探索するラフ作成に限定して使う。採用画像はベクターで描き直し、色、余白、文字、アクセシビリティを人が制御できる状態にする。
